# Codex監督付き実装

> Showcase extract: private milestone名の一部を一般化しているが、実際の責務分離は維持している。

## 今回の依頼

$ARGUMENTS

## 役割

- **Claude Code（主体）**: 正本・HANDOFF・作業計画の確認、コード調査、上位要件からの設計、実装、実行・確認、修正
- **Codex（全体監督）**: Claude Codeの作業方針が上位構造から逸脱していないかだけを確認
- **ユーザー**: 正本・作業計画・コードから一意に決まらない仕様判断

Codexには実装も詳細設計もさせない。

## 1. 依頼と現在地を確認する

依頼に関係する範囲で、

- `docs/handoff/HANDOFF.md`
- `docs/milestones.md`
- 現在の作業計画
- 関連正本

を読み、

- 現在のMilestone / Sub-Milestone
- 今回の目的
- 今回の範囲
- 今回やらない範囲

を把握する。

現在のSub-Milestoneをハードな作業境界として扱う。

## 2. 必要な調査

既存コードは現在の事実を確かめる材料であり、設計の出発点ではない。

```text
上位要件
↓
必要な責務・契約
↓
現行実装との差
↓
必要な修正
```

## 3. 実装前方針

Codexが境界を判断できるだけの短い方針へ圧縮する。

```text
現在のMilestone / Sub-Milestone:
今回の目的:
実装予定範囲:
主な変更点:
意図的に対象外とするもの:
根拠にした正本・作業計画:
```

## 4. Codexによる監督レビュー

新しいCodex threadを1本開始し、sandboxはread-only。

確認させるもの:

- 現在のSub-Milestoneに直接必要な作業だけか
- 後続Milestoneを先回りしていないか
- 対象外領域へ広がっていないか
- 既存実装に引っ張られて上位要件を歪めていないか
- sourceにない値を理由に上流仕様を発明していないか
- 今決める必要のない仕様まで決めていないか
- 「ついでの改善」が混入していないか

詳細設計、実装案、コード、将来機能の提案は求めない。

## 5. Claude Code自身が判定する

Codexの回答を無条件に採用しない。

正本・HANDOFF・作業計画と照合し、Codexが範囲を広げている場合は採用しない。

## 6. 実装する

- 根本修正を優先
- 現在の依頼に不要な領域は変更しない
- 不足値から上流仕様を次々追加しない
- 「将来困るから」で不要な汎用化をしない
- Codexの提案を理由にscopeを拡張しない

## 7. 実装後の確認

repositoryが定める通常の実行・確認を行う。

実際の入口を通せるなら通す。未実行を成功扱いしない。

必要なら同じCodex threadへ変更概要を渡し、Milestone越境の有無だけを再確認させる。

## 8. 最終報告

- 実装した内容
- 変更ファイル
- 実行した確認と結果
- Codex監督レビューの結果
- 後続課題

commit / pushはしない。
