# 共通設計: リポジトリ構成（責務の所在と依存の向き）

> Showcase extract — package構造・Composition Root・依存方向は実際の設計を残す。strategy implementationやprivate config本文は非公開。

## 1. プラットフォームとしての形

```text
Research（専用機）            Development / Control（開発機）        Production Execution（Windows VPS）

Hypothesis / Replay / AI  →    Version Freeze → Review / Approval → Git  → Market Data
Experiment / Dashboard                                                  → Feature
        ↑                                                             → Live Strategy
        │                                                             → Risk / Safety
        └──── read-only / async / idempotent replication ────────────→ Execution
                                                                      → Reconciliation
                                                                      → Audit
```

- **Revenue本体とStrategy Cartridgeの責任を分ける**
- Gitが管理するのはExecution / Risk / Research / Dashboard / Strategy Engine / Registry / Formal config
- Candidateごとの宣言はStrategy Cartridgeとしてcodeから分離
- Research / Productionは同じCartridge validationを使う
- Formal Demo / Liveへ採用したものはreview後に正式configへ昇格する
- ResearchとProductionは**別Composition Root**
- `if mode == research` のような単一application化を避ける
- Platform固有SDKはvenue adapter内へ隔離する

## 2. package責務

| package       | 責務                                                                                                  |
| ------------- | ----------------------------------------------------------------------------------------------------- |
| `core`        | config、secret boundary、time、storage、audit、state、declarations                                    |
| `domain`      | I/OやOSに依らない共通typeとpure logic                                                                 |
| `market_data` | Raw → Normalized → Derived、Replay / Live共通経路                                                     |
| `information` | AI analysis boundary、external research transport、budget / archive                                   |
| `strategies`  | Strategy Engine / Registry / Strategy Cartridge / declaration                                         |
| `evaluation`  | 採否・合否のprojection。注文権限を作らない                                                            |
| `capital`     | economics、allocation、portfolio、scaling、cost allocation                                            |
| `execution`   | Risk → Authority → Send → Reconcile → Recovery                                                        |
| `venues/*`    | provider / broker固有adapter                                                                          |
| `research`    | Replay、Experiment、Dataset、Aggregate、Dashboard、AI Research、Candidate、Shadow、Machine Evaluation |
| `production`  | Production Composition Root、line operation、observation                                              |
| `entrypoints` | CLI。引数を読みRootを呼ぶだけ                                                                         |

### 依存境界

`strategies` はResearch / Production / Executionへ依存しない。

`execution` はStrategy実装、Research、Production compositionへ逆依存しない。

`research` importでProduction adapterやplatform固有SDKを読み込まない。

Production entrypointはResearch / Informationを読み込まない。

## 3. Strategy Cartridge

Current `main` には `src/revenue_project/strategies/cartridge.py` が存在する。

Cartridgeの狙い:

```text
AI / Human Research
        ↓
Candidate Declaration
        ↓
Immutable Cartridge
        ↓
Validation
        ├── Shadow / Research
        └── Demo Execution
                ↓
       adopted candidate only
                ↓
        Formal Git Config
```

Cartridgeはarbitrary Python codeを持つためのpluginではない。

登録済みStrategy Engineへ渡す宣言と、そのfingerprint / validation / correspondenceを持つ。

## 4. Research package

Researchは単なるNotebookではない。

```text
VPS records
   ↓ read-only replication
Dataset
   ↓
Round Trips / Cost / Gross / Net
   ↓
Aggregation
   ├── Dashboard
   ├── Machine Evaluation
   └── AI Input Boundary
             ↓
      3-Agent Research
             ↓
         Candidates
             ↓
      Shadow / Trial
```

Research package自身はProduction permission boundaryのownerではない。
