## 採用した方針

- Candidate Universeを最初から1市場へ固定しない
- Development / Control、Research / Data / AI、Production Executionを分離する
- ResearchとProductionを同一applicationのmode切替だけで混ぜない
- Production ExecutionはResearch machineが停止しても継続可能にする
- ProductionのAudit / Fill evidenceはExecution側がauthoritative writer
- Researchへ送る記録はread-only / asynchronous / non-blocking
- Research artifactをProductionへ直接流さず、version固定・review・approvalを経て昇格する
- Demoの自動運転を使ってUniverse / Signal / Execution feasibilityを探索する
- 探索結果をFormal evaluationのEvidenceへ後付けで混ぜない
- Candidate生成 → Shadow → short Trial → Machine Evaluation → AI Assessment → Human Decisionを分離する
- Revenue本体とStrategy Cartridgeを分離する。Candidateごとの宣言をcodeから分離し、Research / Productionで同じvalidationを使う
